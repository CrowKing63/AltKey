# AI 도구 설정 탭 — 로컬 영역 배치 계획

> `implementation_plan.md`(내장 AI 기능)의 §9 "설정 UX"를 구체화하는 **서브 계획**이다. 이 문서는 settings 탭 레이아웃만 다룬다. 엔진/모델 다운로드·추론 로직 자체는 `implementation_plan.md`의 ModelStore 관할.

> **상태 (2026-11): 구현 완료.** §3의 라디오 + 공통 박스 + 조건부 박스 구조가 `Views/SettingsWindow.xaml` "AI 도구" 탭에 반영됨.

## 1. 배경 (현재 상태)

`Views/SettingsWindow.xaml`의 "AI 도구" 탭(518~560줄)은 현재 **외부 API 세팅만** 담고 있다:

| 순서 | 컨트롤 | 비고 |
|---|---|---|
| 1 | SectionTitle "AI 텍스트 처리" | |
| 2 | API 엔드포인트 URL (TextBox) | |
| 3 | API 키 (TextBox, DPAPI) | |
| 4 | 모델 이름 (TextBox) | |
| 5 | 기본 프롬프트 (TextBox, Height=60, multiline) | **백엔드 공통** |
| 6 | [긴 한글 프롬프트 편집기 열기] (Button) | **공통** |
| 7 | helper TextBlock | **공통** |
| 8 | 타임아웃 (NumericAdjuster) | **백엔드 공통** |
| 9 | [연결 테스트] (Button) | API 전용 |

→ 이미 `ScrollViewer`로 감싸여 있으나, 로컬 영역을 그대로 아래에 붙이면 **총 높이가 커져 하단(로컬)이 창 밖으로 잘림**.

## 2. 목표

- 외부 API + 로컬 모델 두 백엔드를 한 탭에서 고르되, **한 번에 보이는 높이를 제한**해 하단 잘림 방지
- 접근성 우선: 눈만 쓰는 사용자가 **최소 상호작용**으로 원하는 백엔드 세팅에 도달
- 프롬프트·타임아웃은 백엔드 공통이므로 항상 표시

## 3. 설계 — 라디오 + 조건부 섹션 (추천)

```text
┌──────────────────────────────────────────────┐
│ AI 텍스트 처리                              [title]
├──────────────────────────────────────────────┤
│ 백엔드                                        │
│   (•) 외부 API     ( ) 로컬 모델               │
├──────────────────────────────────────────────┤
│ 공통 설정 (백엔드 무관)                        │
│   기본 프롬프트  [TextBox 60px]                │
│   [긴 한글 프롬프트 편집기 열기]                │
│   타임아웃       [NumericAdjuster]             │
├──────────────────────────────────────────────┤
│ ┌─ 외부 API 선택 시 (라디오=외부API) ────────┐ │
│ │  API 엔드포인트 URL [TextBox]              │ │
│ │  API 키 [TextBox]                          │ │
│ │  모델 이름 [TextBox]                       │ │
│ │  [연결 테스트]                              │ │
│ └───────────────────────────────────────────┘ │
│ ┌─ 로컬 모델 선택 시 (라디오=로컬) ──────────┐ │
│ │  [로컬 AI 다운로드]                        │ │
│ │  상태: 엔진 미설치 · 모델 준비됨            │ │
│ │  idle 언로드 [NumericAdjuster 10분]         │ │
│ └───────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

**핵심**: 두 하단 박스 중 **라디오에 따라 하나만 표시**. 그래서 최대 가시 높이 = 공통(4컨트롤) + 활성 섹션(4~5컨트롤)로 제한됨 → 하단 잘림 해결.

### 3.1 프롬프트·타임아웃 이동
- 현재 "API" 섹션 안에 있는 **기본 프롬프트 + 편집기 버튼 + helper + 타임아웃**은 백엔드 공통(`implementation_plan.md` §9)이므로, 라디오 **위쪽의 "공통 설정" 박스**로 올린다.
- API 전용(엔드포인트·키·모델이름·연결테스트)만 조건부 박스에 남김.
- 값 바인딩(`AiDefaultPrompt`, `AiTimeoutSeconds`)은 변경 없음 — 위치만 위쪽으로.

### 3.2 왜 접기(Expander) 대신 라디오+조건부인가 (비교)

| 기준 | 라디오+조건부 (추천) | Expander 접기 |
|---|---|---|
| 상호작용 비용 | 라디오 1클릭으로 백엔드 전환 | 각 섹션 펼치기/접기 클릭 추가 |
| 가시 높이 | 항상 "공통 + 활성 1개"로 제한 | 둘 다 펼쳐면 여전히 높음 |
| 인지 부하 | "하나만 보임" — 단순 | "둘 다 있고 접혀 있음" — 상태 기억 필요 |
| 접근성(눈만) | 적음 (클릭 최소) | 많음 (펼치기 동작 추가) |

→ **눈만 쓰는 사용자**는 메뉴 탐색 비용이 곧 부담이라, 접기 없이 "고르면 바로 그 세팅"인 라디오+조건부가 맞다. Expander는 두 백엔드를 나란히 비교·동시 설정할 필요가 있을 때만 가치가 있는데, ✨는 한 번에 하나만 쓰므로 해당 안 됨.

### 3.3 접기(Expander)를 쓸 경우 (대안 — 비추천)
- WPF `<Expander>`는 네이티브 + `ExpandCollapsePattern` 접근성 지원.
- "외부 API" / "로컬 모델" 두 Expander를 상시 표시하고 각각 접기 가능.
- 단, 둘 다 펼쳐진 상태의 높이는 라디오+조건부보다 큼 → 하단 잘림 리스크 잔존.
- **추천 안 함** (상호작용·높이 모두 불리).

## 4. 제약 / 접근성
- 라디오 그룹: `AutomationProperties.Name="AI 백엔드 선택"`, 각 버튼에 HelpText(외부 API=클라우드, 로컬=오프라인)
- 다운로드 상태(TextBlock)는 **LiveRegion**으로 공지(다운로드 시작/진행/완료/실패) — `implementation_plan.md` §14 접근성 항목과 일치
- 프롬프트·타임아웃 이동은 값 바인딩 변경 없음 — 위치만 위쪽으로

## 7. 수동 검증 체크리스트 (사용자 직접)
1. AI 도구 탭 열기 → "외부 API" 라디오: 공통(프롬프트·타임아웃) + API 박스 표시, 로컬 박스 없음
2. "로컬 모델" 라디오로 전환 → 공통 유지, API 박스 사라지고 로컬 박스(단일 [로컬 AI 다운로드] 버튼 + 상태 + idle) 표시
3. 창 최소 높이에서 하단 잘림 없는지 확인 (둘 중 하나만 보이므로)
4. 프롬프트·타임아웃 값이 백엔드 전환해도 그대로 유지되는지
5. ScreenReader: 라디오 그룹 읽기, 다운로드 상태 LiveRegion 공지 확인
