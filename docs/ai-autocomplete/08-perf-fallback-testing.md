# 08 — 성능·타임아웃·에러 처리 + 통합 테스트

## 목표
AI 자동완성이 **체감 반응성을 해치지 않도록** 타임아웃/에러 경로를 확정하고, 전체 기능(설정→모델→추론→재배치→fallback)을 통합 테스트로 검증한다.

## 배경 (레포 기준)
- 3번 `LayaReranker`가 타임아웃 상한을, 5번이 fallback을, 7번이 캐시를 담당한다. 이 단계는 **그들을 조립해 끝-to-끝으로 검증**한다.
- 자동완성은 키 입력과 직결 → 정확도보다 반응성 우선(기획 15번).

## 작업
1. **타임아웃 정책 확정**:
   - `LayaReranker.RerankAsync` 상한(3번에서 둔 값)이 UI 스레드 블로킹으로 이어지지 않는지 확인.
   - 타임아웃/실패 시 5번이 baseList 원본을 즉시 방출하는지(fallback) 재확인.
2. **에러 상황 체크리스트** (기획 14번, 각 경로가 fallback으로 귀결되는지):
   - 모델 파일 없음 / 손상(SHA-256 불일치)
   - `InferenceSession` 로드 실패
   - 추론 예외
   - 타임아웃
   - AI 결과가 baseList에 없는 단어만 반환(→ 4번이 생략 → 결국 기존 후보)
   - 후보가 아예 없음
3. **성능 smoke**(실제 모델 도착 시):
   - 대표 문맥 10개로 평균/95백분위 추론 시간 측정. 레포 벤치마크 기준 CPU ~30ms/forward pass → 목표는 "한 번의 키 입력 체감에 영향 없음(수십 ms)".
   - **캐시 hit rate는 타이핑 중 낮을 수 있음**(prefix가 매번 바뀌어). 핵심 안전장치는 timeout+fallback이지 캐시가 아님. "추론 미포함 시 fallback이 50ms 이내"를 별도 지표로 측정.
   - 초과면 3번 타임아웃·7번 캐시·후보 수(topN)을 조정하는 knobs을 기록한다.
4. **통합 테스트**(`AltKey.Tests`):
   - fake `LayaReranker` + fake `ModelStore`로 5번 통합 전체 흐름:
     - on+성공 → 재배치, on+실패 → 원본, off → 원본+호출 없음.
   - 7번 캐시 hit/miss가 통합에 반영되는지.
   - 01번 설정 클램핑이 topN으로 전달되는지.

## 하지 말 것
- 성능 목표를 "정확도"로 측정하지 않는다(반응성 기준).
- GUI 체감은 단위 테스트 불가 → 수치 smoke + 백그라운드 실행으로만 확인.
