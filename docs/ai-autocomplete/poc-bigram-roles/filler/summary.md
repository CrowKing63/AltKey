## 근거 요약
- 베이스라인(빈도 폴백)은 모든 케이스에서 동일하게 [리서치, 일단, 이] = 0+1+1 = 2점.
  이 사용자의 빈도 상위어가 화담 입자로, 어떤 문맥에서도 다음 단어로 자연스럽게 오지 못함.
- 모델은 문맥에 맞는 curated 단어를 top으로 올려 1~5점을 분산 (평균 2.90).
- 차이 +27는 게이트 (c) 임계(+15)를 12점 여유로 초과.

## 랜덤 제어 (pool 구성 운 배제)
각 pool 8개 항목 전체에 점수를 매기고, "무작위 top-3"의 기대값(= 3 × pool 평균)을 계산:

| 출처 | 총점 | 모델 대비 |
|---|---:|---:|
| **모델** | 87 | — |
| 빈도 베이스라인 | 60 | -27 |
| 무작위 null (기대값) | 59.25 | +27.75 |

- **빈도 베이스라인(60) ≈ 무작위 null(59.25)** → 빈도 폴백에는 문맥 신호가 없음 (순수 운).
- **모델(87)은 무작위보다 +27.75** → pool에 좋은 단어가 섞여 있어 우연히 잘 뽑힌 것이 아니라,
  모델이 실제로 문맥을 보고 좋은 단어를 top으로 올림. 게이트 (c)의 +15 임계는 pool 구성 운이 아닌
  진짜 문맥 판단으로 확보된 것.

## 베이스라인 정체성 (수정 — 중요)
- **현재 바이그램 모드**: bigram 히트 < 3 → **빈 바** (`AutoCompleteService.cs:97~101`, `Array.Empty<string>`).
  노멀 모드 빈도 상위를 보여주는 게 **아니다**.
- 내가 "빈도 베이스라인"(리서치/일단/이)으로 든 것은 현재 바이그램 모드의 동작이 아니라,
  문서 §2의 **fail-safe**(타임아웃/오류 시 보여줄 "빈도 풀 원본")다.
- 따라서 두 가지 비교가 성립한다:
  - **vs 현재(빈 바)**: 모델 87 vs 0 → 빈 바 대비 가치. 이게 "바이그램 모드 개선"의 본질이다.
  - **vs fail-safe(빈도 풀)**: 모델 87 vs 60 (+27) → "단순 빈도 폴백보다 모델이 값어치 있는가"(비용 정당화).
- 게이트 (a)/(b)/(c)는 둘 다 **fail-safe(빈도 풀)** 대비 정의다 (문서 §5 "베이스라인(빈도)").
  vs 빈 바 비교는 게이트가 아니라 상태대비 가치 확인이다 — (b)의 "0점 개수"는 빈 바에는 정의 불가.
