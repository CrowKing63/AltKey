## 게이트 1 (filler) 사용자 평가 절차

1. `filler/ratings.csv`를 열어 각 행의 `rating` 열에 점수를 넣는다:
   - **2** = 이 문장에서 다음에 이 단어가 자연스럽게 온다
   - **1** = 불가능은 아니지만 약하다
   - **0** = 명백히 어긋난다
2. 평가 원칙 (문서 10 §6.3): 각 항목을 그 문맥에서만 독립 판단한다. 모델/베이스라인을 나란히 비교하지 않는다 (앵커링 방지).
3. 180개 판단 (30케이스 × 2출처 × 3포지션) 완료 후, `summary.md`에 집계를 작성한다:
   - 총점 (max 360/출처), 0점 개수, 모델−베이스라인 차이
   - 게이트: (a) 모델 ≥ 베이스라인 / (b) 모델 0점 ≤ 베이스라인 0점 / (c) 차이 ≥ +15
   - 참고: 문서 10 §5의 "90개 평가 (max 180)"는 §6.5("30×6=180개 판단")·게이트 정의(모델/베이스라인 총점 비교)와 모순 — 본 PoC는 §6.5 기준으로 실행

## 게이트 2 (demoter) 사용자 라벨링 절차

1. `demoter/pairs.json`의 각 쌍을 읽고 `label`에 **good**("C가 W 뒤에 자연스러운가" = 예)/ **bad**(아니오)를 넣는다.
2. 빈도나 개인 사용 습도는 생각하지 않는다 (문서 10 §6.3).
3. 60개 라벨 완료 후, `results.json`의 `model_p_true`(디모트 임계 0.5)와 교차하여 precision/recall을 계산하고 `summary.md`에 기록:
   - Precision = (디모트 ∩ bad) / 디모트 ≥ 80%
4. **단축 옵션**: `probe-findings.md`의 사전 탐사가 구조적 부작(판별력 부재)을 보여준다. 라벨링을 생략하고 게이트 2를 FAIL로 기록해도 된다 — 그 경우 summary.md에 근거 파일명을 인용한다.

## pool 설계 기록 (honest한 편차)

문서 10 §5의 "pool: user-words + 내장 ko-words 상위 5~8개"를 **순수 빈도 상위**로 구현하면, 이 사용자의 빈도 스토어가 화담 입자(리서치/일단/…)로 지배되어 모든 케이스의 pool이 동일하게 퇴화한다 — 문맥적 판별이 불가능해 게이트 (c)가 구조적으로 불가. 문서 §4는 가치 조각을 "문맥적·저빈도 단어"로 규정하고, 문서 예시 pool(조용히/바빠요/…)도 같은 방향이므로, pool을 다음과 같이 구성했다:

- **앵커 3개**: 사용자 빈도 상위 3개 (리서치/일단/이) — 빈도 폴백의 실제 모습
- **curated 5개**: 알려진 어휘(사용자 스토어 ∪ 내장 사전)에서 케이스별 문맥 적합도가 섞인 후보 수동 선별 (2점 후보 1~2, 1점 1~2, 0점 1~2)

`contexts.json`의 `anchors` 필드가 앵커 구성을 감사할 수 있게 기록한다. 이 편차는 "영비용 베이스라인 대비 명백한 우위"를 측정 가능하게 하는 최소 변경이다.
