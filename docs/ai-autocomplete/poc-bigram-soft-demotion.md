# PoC — 초소형 결정 모델의 제한적 감점 재평가

> **목적**: 모델이 다음 단어를 생성하거나 좋은 후보를 찾아내도록 하지 않는다. 기존 바이그램 후보 중 **명백히 문맥에 맞지 않는 후보만** 낮은 신뢰도로 감지해 순위를 조금 낮출 수 있는지 검증한다.
>
> **상태**: 설계안. 아직 실행·통과한 결과가 아니다.
>
> **관계**: `10-bigram-mode-model-roles.md`의 demoter PoC를 대체하기보다, 기존 단순 쌍 판별 실패를 반영해 **후보군 내 상대 비교 + 제한적 감점 + 순위 손실 측정**으로 재설계한다. 기존 `09-model-viability.md`의 AI 자동완성 포기 결정은 이 PoC가 통과하기 전까지 유효하다.

## 1. 가설과 범위

**가설**: 초소형 결정 모델의 한국어 이해가 완전하지 않아도, 낮은 count의 바이그램 후보 중 다른 후보보다 유난히 어색한 항목을 높은 정밀도로 식별할 수 있다. 이를 삭제하거나 위로 올리는 대신 한두 자리만 뒤로 보내면, 잘못된 판단의 비용을 제한하면서 노이즈를 줄일 수 있다.

- 입력은 이미 생성된 바이그램 후보만 사용한다. 모델의 단어 생성·후보 추가는 금지한다.
- 원래 순위와 count를 보존한다. 신뢰도가 낮은 후보와 상위 count 후보는 변경하지 않는다.
- 감점은 순위 하향만 허용하며 최대 1~2자리로 제한한다. 후보를 숨기거나 제거하지 않는다.
- 모델 오류·시간 초과·불확실한 출력은 원래 순서로 되돌린다.
- 이 PoC의 판단 대상은 **순위 조정의 순효과**다. 모델의 절대적인 한국어 능력이나 다음 단어 top-1 정확도를 주장하지 않는다.

## 2. 이전 demoter 결과에서 반영할 점

`poc-bigram-roles/demoter/probe-findings.md`에서 기존 laya-ko는 여러 질문 인코딩에서 good/bad 쌍의 점수 분리가 없었고, 60개 점수 대부분이 0.5 미만이었다. 따라서 다음을 전제로 삼지 않는다.

1. `p_true < 0.5`를 어색함으로 간주하지 않는다. 이전 점수 분포상 대부분을 감점하는 결과가 될 수 있다.
2. 개별 쌍에 "자연스러운가?"라고 묻는 한 가지 인코딩만으로 재시험하지 않는다. 후보군 안에서 **어느 후보가 특히 덜 자연스러운가**를 비교하는 입력 형식도 별도 실험군으로 둔다.
3. 기존 60쌍 결과는 라벨이 없으므로 성능의 증거로 재사용하지 않는다. 모델 출력 형식·후보 선택의 참고 자료로만 둔다.
4. 새 PoC가 모델/인코딩 선택에서 기존 실패를 재현하면 사용자 라벨링 확대 전에 중단한다.

## 3. 데이터셋

### 3.1 표본 구성

- **개발·임계값 보정 세트**: 30개 문맥.
- **잠금 평가 세트**: 별도 120개 문맥. 개발 세트와 동일한 원문·문장·바이그램 쌍이 겹치지 않게 한다.
- 각 문맥은 실제 사용자 바이그램 후보 4~8개와 해당 시점의 count를 포함한다. 가능하면 count 1~2 후보가 여러 개 있는 문맥을 우선 표집한다.
- 표본은 한두 개 prev에 편중되지 않게 구성하고, 표집 규칙·시드·원본 데이터 버전을 기록한다. 한 문맥의 후보는 통계 집계에서 독립 표본처럼 과대 계산하지 않는다.
- 각 문맥에는 직전 단어만이 아니라 가능한 경우 직전 3~5단어를 포함한다. 문장 문맥을 복원할 수 없는 경우는 `context_scope: bigram_only`로 표시하고 별도 결과를 보고한다.
- 개인정보나 원문 대화 기록을 새로 수집하지 않는다. 저장된 바이그램 데이터에서 필요한 최소 문맥만 구성하고, 문맥을 수동 구성한 경우 그 사실을 명시한다.

### 3.2 라벨

평가자는 후보 각각을 문맥에 이어 썼을 때의 자연스러움으로 라벨링한다.

- `2`: 자연스럽고 문맥에 잘 맞음
- `1`: 가능하지만 덜 자연스럽거나 문맥 정보만으로 판단하기 어려움
- `0`: 문맥상 명백히 어색함

빈도나 count를 보고 자연스러움을 판단하지 않는다. 라벨링 화면/시트에는 모델 점수와 모델이 감점 대상으로 고른 항목을 노출하지 않는다. 가능하면 문맥별 후보 순서를 무작위화한다.

**주요 이진 기준**: `0`만 명백한 어색함(negative), `1`과 `2`는 보호할 후보(positive). 애매한 1점을 별도 민감도 분석에서 제외해 결과가 뒤집히는지 확인한다.

## 4. 비교할 모델 입력·정책

같은 모델 체크포인트와 토크나이저를 고정하고 다음 방식을 비교한다.

- **A — 기존 쌍 판정 재현**: 후보별로 문맥 뒤에 후보를 붙여 적합도를 점수화한다. 이전 인코딩을 가능한 한 그대로 재현해 실패 재발 여부를 확인한다.
- **B — 후보군 상대 선택**: 한 문맥과 4~8개 후보를 함께 제시해 가장 어색한 후보 또는 어색함이 뚜렷한 후보를 고르게 한다. 모델 인터페이스가 허용하면 상위 1개만이 아니라 후보별 확률/점수도 기록한다.
- **C — 점수 차이 기반 보수 정책**: B 또는 A의 점수만 사용하되, 개발 세트에서 정한 임계값과 최소 점수 차를 동시에 만족할 때만 감점한다. 점수가 낮다는 이유만으로 단독 감점하지 않는다.

A/B/C는 탐색 비교용이다. 잠금 평가 세트를 보고 유리한 방식을 고르거나 임계값을 조정하지 않는다. 개발 세트에서 하나의 정책을 선택·고정한 뒤 잠금 평가 세트에 단 한 번 적용한다. 모델이 후보별로 일관된 비교 점수를 제공하지 못하면 C를 억지로 만들지 않고 해당 방식은 실행 불가로 기록한다.

## 5. 순위 조정 정책 — 실험 파라미터

정책은 잠금 평가 전에 고정한다.

1. 후보는 count 오름차순/내림차순으로 재구성하지 않는다. 입력 순서는 기존 baseline이 정한 순서를 기준으로 한다.
2. 기본 대상은 count ≤ 2인 후보 중 baseline 상위 3위 바깥 후보로 제한한다. count가 더 높거나 상위 3위인 후보는 모델이 감점할 수 없다.
3. 후보의 명백한 어색함 점수가 개발 세트의 임계값을 넘고, 다음 후보와의 점수 차가 최소 margin을 넘을 때만 감점한다.
4. 한 문맥에서 감점 가능한 후보는 최대 1개로 시작한다. 감점 이동폭은 정확히 1자리로 고정한다. 별도 사전 등록된 안전성 비교군에서만 최대 2자리 정책을 검토한다.
5. 상대 후보의 기존 순서는 유지하고, 동점·불확실·모델 실패는 baseline 순서를 유지한다.

초기 실험의 주 정책은 **최대 1자리 감점**이다. 최대 2자리 비교는 별도의 결과로 보고하며, 주 정책 결과를 대체하지 않는다. 이는 실제 제품 설정값이 아니라 제한적 효과를 검증하는 PoC 파라미터다.

## 6. 평가 기준과 사전 게이트

### 게이트 0 — 실행 가능성

- 고정 입력·출력의 반복 추론 결과가 결정적인지 확인한다.
- 본머신 CPU에서 토크나이징 포함 문맥당 추론 지연 p50/p95, 메모리, 모델 다운로드 크기를 기록한다.
- 제품 적용 후보의 기준은 p50 ≤ 150ms, p95 ≤ 300ms로 둔다. 이 게이트는 단어 수락 후 비동기 처리라는 역할에만 적용한다.
- 오류·타임아웃 시 baseline 순서가 그대로 반환되는 자동 검증을 통과해야 한다.

### 게이트 1 — 명백한 어색함의 식별 정밀도

잠금 세트에서 감점 대상으로 선택된 후보만 평가한다.

- **정밀도(주요 지표)** = 감점 대상 중 라벨 0인 수 / 전체 감점 대상 수
- 통과 기준: 정밀도 ≥ 90%, 그리고 감점 대상이 최소 20개. 20개 미만이면 판정 보류(긍정 증거 부족)로 한다.
- 0점 후보를 얼마나 찾아냈는지(재현율)는 참고 지표로 보고한다. 재현율을 높이기 위해 정밀도를 희생하지 않는다.
- 라벨 1을 보호 대상으로 포함한 주 분석을 통과해야 한다. 1점을 제외한 민감도 분석에서만 통과하는 경우 전체 통과로 보지 않는다.

### 게이트 2 — 전체 순위에 주는 이득과 피해

동일 문맥에 대해 baseline 순서와 모델 적용 순서를 비교한다.

- **좋은 후보 손상률**: baseline 대비 한 자리 이상 내려간 라벨 1·2 후보 수 / 전체 라벨 1·2 후보 수. 기준 ≤ 2%.
- **명백한 어색 후보 개선률**: baseline 대비 순위가 오른 라벨 0 후보 수 / 순위를 바꿀 수 있었던 라벨 0 후보 수. 참고값으로 보고한다.
- **문맥 단위 순효과**: 라벨에 기반한 순위 비용을 사전 고정해 baseline과 정책의 차이를 계산한다. 권장 비용은 `라벨 2: 0`, `라벨 1: 1`, `라벨 0: 3`에 후보의 최종 순위를 곱한 합이다. 잠금 세트 전체 합과 문맥별 차이를 모두 제시한다.
- 통과 기준: 잠금 세트 전체 순위 비용이 baseline보다 낮고, 좋은 후보 손상률이 2% 이하이며, 사용자 평가에서 눈에 띄는 반복적 역전 사례가 없어야 한다.
- 문맥 단위 부트스트랩 95% 신뢰구간을 함께 보고한다. 신뢰구간이 0을 포함하면 이득이 확실하다고 말하지 않고 **판정 보류**로 처리한다.

### 종합 판정

- **통과**: 게이트 0, 1, 2 모두 통과. 제한적 감점 역할에 한해 구현 기획을 별도 작성할 근거가 된다. 제품 채택 자체를 자동 승인하지 않는다.
- **실패**: 게이트 1 정밀도 미달, 좋은 후보 손상률 초과, 순위 비용 악화 중 하나라도 발생.
- **보류**: 표본 부족, 잠금 라벨의 애매함, 신뢰구간이 0을 포함하거나 모델 출력이 안정적이지 않아 결론 불가.
- 실패·보류면 기존 baseline을 유지하고, 점수 임계값을 결과에 맞춰 사후 조정해 통과로 바꾸지 않는다.

## 7. 실행 순서

1. 모델·토크나이저·실행 환경을 고정하고 체크포인트 해시를 기록한다.
2. 30개 개발 문맥과 120개 잠금 문맥을 분리 구성한다. 중복·후보 수·count 분포를 자동 검증한다.
3. 게이트 0을 실행한다. 실패하면 사용자 라벨링 전에 종료한다.
4. 개발 세트에서 A/B/C 형식과 감점 임계값·margin을 탐색한다. 개발 라벨은 모델 결과를 보기 전에 먼저 수집한다.
5. 정책 하나, 이동폭, 보호 조건, 임계값을 문서에 고정한다.
6. 잠금 세트를 블라인드 라벨링하고, 모델의 잠금 출력은 라벨 고정 후에 산출·공개한다.
7. 자동 집계 스크립트로 precision, 손상률, 순위 비용, 신뢰구간을 계산한다. raw 데이터와 스크립트 버전을 보존한다.
8. 판정과 무관하게 부작용 사례를 전부 기록한다. 통과하더라도 실제 UI·지연·접근성 검증은 후속 단계다.

## 8. 산출물과 데이터 형식

권장 디렉터리: `docs/ai-autocomplete/poc-bigram-soft-demotion/`

- `README.md`: 실행 환경, 고정된 게이트, 판정
- `development.json`: 개발 문맥·후보·count·모델 입력/점수
- `locked-cases.json`: 잠금 문맥·후보·count (정답 라벨과 분리 보관)
- `labels.csv`: case_id, candidate, rating, evaluator_note
- `predictions.json`: 원점수, 선택 정책, 감점 여부, baseline/final rank
- `summary.md`: 게이트 결과, 신뢰구간, 전체 부작용 사례
- `aggregate.py`: raw 파일에서 모든 지표를 재계산하는 스크립트

케이스 스키마 예시:

```json
{
  "id": "locked-001",
  "context": ["오늘", "회의에서", "이", "문제를"],
  "context_scope": "reconstructed_4_tokens",
  "candidates": [
    {"word": "논의했고", "count": 2, "baseline_rank": 1},
    {"word": "아름답다", "count": 1, "baseline_rank": 2}
  ],
  "model_scores": null,
  "labels": null
}
```

예시는 스키마 설명용 가상 데이터이며 실측·평가 결과가 아니다. 실제 문맥으로 오인하지 않도록 raw 데이터와 분리한다.

## 9. 해석상의 한계

- 기존 사전 탐사에서 laya-ko 쌍 판정은 실패했다. 후보군 상대 비교가 개선될 것이라는 보장은 없다.
- 짧은 바이그램 문맥만으로는 담화 의도·말투·생략을 복원할 수 없다. `bigram_only`와 복원 문맥 결과를 섞어 단일 수치로 과장하지 않는다.
- 한 명의 사용자가 평가한 결과는 해당 사용자의 문맥 판단에 대한 근거이지, 모든 한국어 사용자에 대한 일반화가 아니다.
- 사용자 바이그램은 작성 습관·주제에 편향된다. 이 PoC는 일반 한국어 품질 벤치마크가 아니다.
- 통과해도 모델 다운로드·상주 메모리 비용, 실제 입력 중 동작, 사용자에게 감점 사실을 설명하는 UI의 필요성은 별도 결정이다.
- 필요 시 추가 사용자 평가를 받기 전에는 작성 코드의 구현·통합을 시작하지 않는다.
