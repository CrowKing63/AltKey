# AltKey AI 자동완성 기능 기획서

## 1. 개요

AltKey의 기존 자동완성 기능에 소형 AI 결정 모델을 추가하여, 기존 자동완성 후보 중 현재 문맥에 가장 적합한 단어를 AI가 선별하고 우선적으로 표시하도록 한다.

핵심 방향은 **AI가 단어를 직접 생성하는 것이 아니라, AltKey가 기존 방식으로 생성한 후보를 AI가 재평가(reranking)하는 것**이다.

이를 통해 기존 자동완성의 빠르고 안정적인 동작은 유지하면서, 단순 빈도와 Bigram만으로 판단하기 어려운 문맥 적합성을 보완한다.

AI 모델로는 초소형 결정 모델인 Laya 계열, 특히 한국어용 `laya-ko`를 우선 검토한다.


## 2. 목표

기존 AltKey 자동완성의 장점을 유지하면서 다음을 개선한다.

- 현재 문맥에 더 적합한 자동완성 후보를 우선 표시
- 사용자의 실제 문장 흐름에 맞는 다음 단어 선택
- 기존 사용자 빈도 및 Bigram 학습 데이터 활용
- AI가 새로운 단어를 임의로 생성하지 않도록 제한
- 별도의 AI 서버나 Python 환경 없이 로컬에서 동작
- 자동완성 기능을 켜면 필요한 AI 모델을 자동으로 설치 및 로드
- AI 기능을 사용하지 않는 사용자는 기존 자동완성을 그대로 사용


## 3. 기본 설계 원칙

AI는 기존 자동완성 시스템을 대체하지 않는다.

기존 시스템이 먼저 후보를 생성하고, AI는 그 후보 가운데 문맥상 적절한 후보를 선택한다.

```text
사용자 입력
    ↓
기존 AltKey 자동완성
    ├─ 사용자 단어 빈도
    ├─ 기본 사전
    ├─ Bigram
    └─ Prefix / 초성 검색
    ↓
기존 후보 목록
    ↓
AI 결정 모델(Laya)
    ↓
문맥 적합도가 높은 후보 선별
    ↓
최종 자동완성 목록
```

따라서 AI 모델의 오류가 발생하더라도 기존 자동완성 시스템으로 fallback할 수 있다.


## 4. 후보 생성과 AI의 역할 분리

기존 AltKey가 다음과 같은 후보를 생성한다고 가정한다.

```text
오늘 날씨가

좋다
좋네요
맑다
흐리다
어떻다
```

AI에는 이 후보들을 전달한다.

AI는 다음과 같이 판단할 수 있다.

```text
좋네요
좋다
맑다
```

최종 결과는:

```text
1. 좋네요   ← AI 선택
2. 좋다     ← AI 선택
3. 맑다     ← AI 선택
4. 흐리다   ← 기존 후보
5. 어떻다   ← 기존 후보
```

AI가 존재하지 않는 새로운 단어를 생성하는 것이 아니라 기존 후보를 선택하기 때문에 안정성이 높다.


## 5. AI 후보 표시 방식

초기 버전에서는 가장 단순한 방식을 사용한다.

**AI가 선택한 상위 후보를 기존 후보보다 앞에 배치한다.**

예:

```text
기존 후보:
1. 합니다
2. 하고
3. 하는
4. 하니까
5. 하지만

AI 선택:
하지만
합니다

최종:
1. 하지만   ★ AI
2. 합니다   ★ AI
3. 하고
4. 하는
5. 하니까
```

AI가 선택한 단어가 기존 목록에 이미 존재하는 경우에는 중복 표시하지 않고 해당 단어를 앞쪽으로 이동시킨다.


## 6. 사용자 설정

기존 자동완성 설정과 별도로 AI 기능을 켜고 끌 수 있도록 한다.

예시:

```text
자동 완성
☑ 자동 완성 사용

AI 자동 완성
☑ AI 후보 사용

AI 모델
Laya Korean

AI 후보 수
[ 3 ]

AI 후보 배치
● AI 후보를 앞에 배치
○ AI 점수순으로 전체 재정렬
```

첫 번째 구현에서는 설정을 최소화하여 다음 정도만 제공해도 충분하다.

```text
☑ AI 자동완성 사용
AI 후보 수: 3
```

AI 기능을 끄면 기존 AltKey의 동작에는 영향을 주지 않는다.


## 7. AI 모델 배포

사용자가 별도의 AI 프로그램을 설치할 필요가 없도록 한다.

AltKey 자체가 필요한 모델을 관리한다.

```text
AltKey 실행
    ↓
AI 자동완성 활성화 여부 확인
    ↓
모델 존재 확인
    ↓
없음 → 모델 다운로드
있음 → 바로 로드
    ↓
로컬 AI 자동완성 사용
```

모델은 AltKey가 관리하는 전용 디렉터리에 저장한다.

예:

```text
AltKey/
└─ models/
   └─ laya-ko/
      ├─ model.onnx
      ├─ model.onnx.data
      ├─ tokenizer.json
      └─ manifest.json
```

`manifest.json`에는 모델 버전, 파일 크기, SHA-256 등의 정보를 저장하여 모델 업데이트와 무결성 검사를 지원한다.


## 8. 로컬 추론 방식

가능하면 Python이나 별도의 Laya 서버에 의존하지 않고 AltKey 내부에서 직접 모델을 실행한다.

권장 구조:

```text
AltKey.exe
    │
    ├─ AutoCompleteService
    │
    ├─ KoreanDictionary
    ├─ EnglishDictionary
    ├─ BigramFrequencyStore
    │
    └─ LayaReranker
            │
            └─ ONNX Runtime
                    │
                    └─ laya-ko.onnx
```

Laya 모델은 ONNX 형태로 공개되어 있으며, 로컬 ONNX Runtime으로 CPU에서 추론한다.

이렇게 하면 사용자는 Python, Ollama, 별도 AI 서버 등의 설치가 필요 없다.


## 9. 모델 상주 방식

AI 자동완성이 활성화된 경우 모델을 한 번 메모리에 로드한 뒤 계속 재사용한다.

```text
AltKey 시작
    ↓
Laya 모델 로드
    ↓
자동완성 요청
    ↓
Laya 추론
    ↓
결과 캐시
    ↓
다음 요청에서 재사용
```

매번 모델을 로드하는 방식은 사용하지 않는다.

필요하다면 향후 장시간 미사용 시 모델을 unload하여 메모리를 회수하는 기능을 추가할 수 있다.


## 10. 캐시 구조

문맥별 AI 결과를 메모리에 캐시할 수 있다.

예:

```text
Context:
오늘 날씨가

AI candidates:
좋다
좋네요
맑다
```

사용자가 다음 단어를 확정하면 해당 문맥을 기준으로 다음 후보를 다시 계산한다.

```text
오늘 날씨가 좋네요
        ↓
Laya
        ↓
정말 / 너무 / 생각보다 / ...
```

최근 문맥을 제한적으로 캐시하여 불필요한 반복 추론을 방지한다.


## 11. 기존 AltKey와의 통합 위치

현재 구조를 최대한 유지한다.

기존:

```text
AutoCompleteService
    ↓
KoreanDictionary / EnglishDictionary
    ↓
BigramFrequencyStore
    ↓
후보 표시
```

변경:

```text
AutoCompleteService
    ↓
KoreanDictionary / EnglishDictionary
    ↓
BigramFrequencyStore
    ↓
기존 후보 생성
    ↓
LayaReranker
    ↓
AI 후보 우선 배치
    ↓
후보 표시
```

핵심 구현 위치는 기존 `GetSuggestions()` 계열의 후보 생성 이후와 `AutoCompleteService`의 후보 처리 부분이다.

AI 기능을 별도의 서비스로 분리하여 기존 Dictionary 코드와 직접 결합하지 않는 것을 권장한다.


## 12. AI 입력 데이터

Laya에는 다음과 같은 정보를 전달하는 것을 검토한다.

```text
이전 문맥:
오늘 날씨가

후보:
좋다
좋네요
맑다
흐리다
어떻다
```

AI의 역할은:

> 현재 문맥에서 다음에 올 가능성이 가장 높은 후보를 선택

하는 것이다.

필요하다면 후보별 점수 또는 순위를 얻어 상위 N개를 선택한다.


## 13. 기존 점수와 AI 점수의 관계

첫 버전에서는 AI가 선택한 후보를 단순히 앞쪽으로 이동하는 방식으로 시작한다.

즉:

```text
AI 선택 여부
    >
기존 자동완성 순위
```

의 우선순위를 사용한다.

향후 충분한 사용 데이터를 확보하면 다음과 같은 통합 점수 방식으로 발전시킬 수 있다.

```text
FinalScore =
    기존 빈도 점수
  + Bigram 점수
  + AI 문맥 점수
```

AI가 기존 학습 데이터를 완전히 무시하지 않도록 하는 것이 중요하다.


## 14. AI가 실패했을 때의 동작

다음 상황에서는 기존 자동완성으로 fallback한다.

- 모델 로드 실패
- 모델 파일 손상
- AI 추론 오류
- 추론 시간 초과
- AI 결과가 유효하지 않음
- 후보가 존재하지 않음

예:

```text
AI 정상
→ AI 후보 + 기존 후보

AI 실패
→ 기존 후보만 표시
```

사용자가 AI 기능을 켰다는 이유로 자동완성 자체가 작동하지 않는 상황은 피한다.


## 15. 성능 목표

AI 자동완성은 일반적인 생성형 AI보다 훨씬 작은 지연시간을 목표로 한다.

중요한 것은:

- 모델을 한 번만 로드
- CPU 로컬 추론 가능
- 후보 수 제한
- 단어 확정 시점에 다음 후보를 미리 계산
- Prefix 입력 중에는 캐시 사용
- AI 추론 실패 시 즉시 기존 엔진 사용

특히 자동완성은 사용자의 키 입력과 직접 연결되어 있으므로 정확도보다 먼저 **체감 반응성을 유지하는 것**이 중요하다.


## 16. 모델 후보

1차 대상(출처 확인됨):

```text
laya-ko (2nugu/laya-ko-decision-onnx)
약 322M parameter, mmBERT-base + 결정 헤더
ONNX 공개(model.onnx + model.onnx.data), Apache-2.0
CPU ~30ms/forward pass
```

Laya는 텍스트 생성 모델이 아니라 결정 모델(choice 질문 → 각 옵션별 확률)이므로 "기존 후보 rerank" 용도와 구조적으로 잘 맞는다. ONNX 가중치와 입력 시그니처(`input_ids`, `attention_mask`, `marker_pos`, `marker_mask`, `qtype`)가 공개되어 있어 02·03번의 전제가 확정된다.

추후 실제 AltKey 사용 로그가 축적되면 AltKey 전용 데이터셋을 만들어 Laya를 자동완성 후보 선택 문제에 맞게 fine-tuning하는 것도 가능하다.


## 17. 최종 UX

사용자 입장에서는 복잡한 AI 시스템으로 보이지 않는 것이 좋다.

```text
AltKey 설정

자동 완성
☑ 자동 완성 사용

AI 자동 완성
☑ AI 후보 사용
    모델: Laya Korean
    AI 후보 수: 3
```

이후 사용자는 평소처럼 타이핑한다.

AI 모델의 설치, 로딩, 후보 평가, 캐싱은 AltKey가 내부적으로 처리한다.

결과적으로 AltKey는 기존의 빠른 사전/빈도 기반 자동완성에 **로컬 초소형 AI의 문맥 판단 능력을 추가한 하이브리드 자동완성 시스템**이 된다.


## 18. 핵심 결론

이 기능의 핵심은 **“AI가 자동완성을 대신한다”가 아니라 “기존 자동완성 후보 중 AI가 더 적절한 후보를 골라 앞에 배치한다”**는 것이다.

따라서 기존 AltKey의 안정성과 속도를 유지하면서 AI 기능을 선택적으로 추가할 수 있다.

특히 Laya와 같은 초소형 결정 모델을 ONNX 형태로 AltKey에 직접 포함시키면 별도의 AI 서버나 Python 환경 없이 완전한 로컬 AI 자동완성이 가능하다.

최종 구조는 다음과 같다.

```text
                  ┌─ 사용자 빈도
                  ├─ 사전
입력 ─────────────┼─ Bigram
                  └─ Prefix
                       │
                       ▼
                기존 후보 10~20개
                       │
                       ▼
                  Laya Korean
                  AI 재평가
                       │
                       ▼
                AI 상위 3개
                       │
                       ▼
          AI 후보 우선 + 기존 후보
                       │
                       ▼
                  자동완성 UI
```
