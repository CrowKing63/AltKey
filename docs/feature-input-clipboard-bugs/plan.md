# 빠른 메모 한글 입력·클립보드 붙여넣기 버그 수정 계획

> 상태: 계획 — 원인 확인 및 수정 전 사용자 검토용. 구현은 별도 승인 후 진행한다.

## 1. 증상과 현재 확인된 구조

| 증상 | 현재 확인된 코드 경로 | 아직 확인이 필요한 점 |
|---|---|---|
| 빠른 메모에서 VirtualKey 모드 한글 조합이 안 되어 Unicode 고정으로 우회 중 | `KoreanInputModule.HandleKey()`는 VirtualKey 경로에서 조합을 직접 화면에 출력하지 않고 입력을 통과시키며, 주석상 OS IME가 조합을 처리하도록 설계됨 (`AltKey/Services/InputLanguage/KoreanInputModule.cs:113-135`) | 빠른 메모가 활성일 때 AltKey의 한글/OS IME 상태, 입력 이벤트의 대상 HWND, VK_HANGUL 토글 전달, WPF TextBox의 IME 처리·포커스가 어떻게 상호작용하는지 재현/로그로 분리해야 한다. 아직 원인을 단정하지 않는다. |
| 클립보드 붙여넣기가 탐색기 검색 필드 및 빠른 메모에서 실패 | `ClipboardViewModel.PasteItem()`은 먼저 클립보드를 갱신하고 `PrepareInputTarget`/`RestoreInputTarget`을 호출한 다음 `InputService.HandleAction(Ctrl+V)`를 보냄 (`AltKey/ViewModels/ClipboardViewModel.cs:189-207`) | 검색 필드의 입력 대상 핸들이 일반 앱과 다른지, 빠른 메모의 포커스 확보가 Ctrl+V 시점에 완료되는지, `SendCombo` 경로가 해당 대상에서 동작하는지 각각 확인한다. |
| 이전 리뷰 P1: 닫기 설정 OFF 상태에서 창 전환 후 오래된 앱으로 붙여넣을 수 있음 | `ClipboardPanelWindow`의 `_previousForeground`를 열 때 캡처하고 복원 후 유지함 (`AltKey/Views/ClipboardPanelWindow.xaml.cs:26-30, 70-85, 90-121`) | 재현을 통합 테스트/수동 검증으로 확정하고, 현재 활성 외부 앱을 의도적으로 존중할 조건과 패널이 포커스를 잡은 경우의 대상 갱신 규칙을 명시한다. |

## 2. 목표와 비목표

### 목표
- 빠른 메모에서 OS IME의 한글 자모 조합이 가능한지 원인을 규명하고, 지원 가능한 입력 모드에서 일관된 입력 UX를 제공한다.
- 클립보드 항목 선택 후 Ctrl+V가 파일 탐색기 검색 필드, 빠른 메모, 일반 텍스트 필드에서 올바른 대상에 들어가게 한다.
- 붙여넣기 대상 복원은 현재 사용자가 의도한 대상 창을 보존하고, 과거 HWND로 잘못 전송하지 않는다.
- 기존 VirtualKey/Unicode·자동완성·조합 동작의 보호 규칙과 접근성을 유지한다.

### 비목표
- HangulComposer 조합 알고리즘 재설계.
- 관리자 권한/입력 모드 정책 변경.
- 클립보드 UI 재디자인 또는 이슈와 무관한 포커스 구조 변경.

## 3. 조사·설계 순서

### 단계 A — 재현 기준선과 로그
1. 변경 전 상태에서 세 경로를 각각 재현한다: (a) 빠른 메모에 OS IME 한글 입력, (b) 탐색기 검색 칸에 클립보드 붙여넣기, (c) 빠른 메모에 클립보드 붙여넣기.
2. 각 실행에서 AltKey 실행 권한, `InputService.Mode`, OS 입력 언어/IME 상태, 포그라운드 HWND/PID, 포커스된 WPF 요소, 붙여넣기 직전·직후 포그라운드, 전송 이벤트가 태그된 SendInput인지 기록한다. 사용자 텍스트/클립보드 본문은 진단 로그에 남기지 않는다.
3. 기존 `ClipboardTrace`는 Release 빌드에서도 호출/인자 평가가 제외되는지 확인한다. 입력 내용이나 민감한 텍스트가 기록되지 않게 한다.
4. 일반 텍스트 편집기와 외부 앱 창을 기준 대조군으로 두어 대상 앱 특이성인지 AltKey 경로 문제인지 분리한다.

### 단계 B — 빠른 메모 IME 원인 분석
1. 실제 입력 경로가 VirtualKey인지 확인: `KeyButton` → `KeyboardViewModel` → `InputService`의 이벤트 순서와 메모 TextBox 포커스를 추적한다.
2. 메모가 포커스일 때 AltKey 내부 `KoreanInputModule`이 자모를 가로채거나 Finalize/Cancel하는지, OS IME가 받은 VK 이벤트가 조합을 시작하는지 확인한다.
3. Windows IME 상태가 앱/스레드/포커스 대상에 따라 달라지는지 확인한다. 상단바 `VK_HANGUL`과 AltKey의 `가/A` 서브모드는 서로 다른 기능임을 유지한다.
4. 조사 결과에 따라 수정 경로를 좁힌다: 대상 창 포커스/IME 컨텍스트 문제면 입력 대상·포커스 전달을 수정하고, 키 이벤트 경로 문제면 메모 대상에서만 적절한 VK 경로를 복원한다. Unicode 강제는 임시 우회로인지 확인 전까지 기본 UX로 간주하지 않는다.

### 단계 C — 클립보드 입력 대상 수명주기
1. `PrepareInputTarget`과 `RestoreInputTarget`의 소유·호출 순서를 추적한다. `ClipboardService.PasteItem()`이 대상 포커스 준비 전에 시스템 클립보드를 바꾸는 점도 검증한다.
2. 동작 계약을 정한다:
   - 패널이 포커스를 가진 상태에서 선택하면 열기 당시 외부 입력창을 대상으로 붙여넣는다.
   - 패널이 백그라운드이고 사용자가 다른 외부 앱으로 이동했다면 현재 외부 포그라운드를 대상으로 삼고, 저장된 오래된 핸들로 되돌리지 않는다.
   - 빠른 메모가 명시적 입력 대상이면 그 TextBox를 확보한 뒤 붙여넣고, 외부 복원은 하지 않는다.
   - 대상 HWND가 무효이거나 포그라운드 전환 실패면 잘못된 창으로 Ctrl+V를 보내지 않고 안전하게 중단한다.
3. 파일 탐색기 검색 필드와 WPF 빠른 메모를 별도 대상으로 테스트한다. Ctrl+V 전송이 포커스 전환 완료 후에만 일어나도록 동기화/대기 책임을 한 곳에 둔다.
4. 클립보드 내용을 시스템에 설정하는 것과 Ctrl+V 전송을 분리해 실패 처리 기준을 검토한다. 보내기 실패가 감지되면 조용히 다른 대상에 보내지 않는다.

### 단계 D — P1 수정
- `_previousForeground`를 단순히 매번 재사용하지 않는다. 패널 활성/비활성 및 외부 포커스 전환을 기준으로 현재 대상 후보를 갱신하는 명시적 상태 전이를 설계한다.
- 대상 우선순위는 빠른 메모 명시 대상 → 사용자가 현재 선택한 외부 앱 → 패널 열기 직전의 유효한 외부 앱 폴백으로 한다.
- 상태 전이는 UI Dispatcher에서 직렬화하고, 숨김·닫기·붙여넣기·앱 종료 경로에서 오래된 HWND가 남지 않게 한다.
- 같은 정책을 클릭 붙여넣기와 Enter 붙여넣기에 공통 적용한다.

## 4. 자동완성·한글 보호 규칙

| 보호 규칙 | 계획에서의 준수 |
|---|---|
| `HangulComposer`의 내부 알고리즘/CompositionDepth를 변경하지 않음 | IME 포커스·이벤트 경로 조사로 제한한다. 조합기 로직 수정이 필요해 보이면 별도 설계 검토와 전체 조합 회귀 검증 전에는 건드리지 않는다. |
| `InputService.Mode` 관리자/일반 결정 정책 변경 금지 | 설정값으로 모드를 강제하지 않는다. 현재 실행 모드에서 재현한다. |
| `KoreanInputModule`과 `SendAtomicReplace` 계약 유지 | 키 입력 분기 변경이 필요하면 보호 문서 §2를 재검토하고 Unicode 추적 길이 테스트를 추가한다. |
| OS IME VK_HANGUL과 AltKey `가/A` 서브모드 독립 유지 | OS 입력 언어 전환 문제와 AltKey 입력 모드를 분리 진단한다. |
| 모든 이벤트는 WPF Dispatcher에서 처리 | 포커스/상태 갱신을 UI 스레드에서 직렬화한다. |
| 입력 이벤트 재진입 방지 | SendInput 경로가 `INPUT_EXTRAINFO_ALTKEY` 태그를 사용하는지 확인하고, WH_KEYBOARD_LL 훅이 태그된 입력을 무시하는 회귀 테스트를 유지한다. |

## 6. 테스트 계획

### 단위/자동화 테스트
- 붙여넣기 대상 선택 정책: own target, 현재 외부 포그라운드, 저장된 유효 외부 핸들 폴백, 무효 핸들.
- 패널을 열린 채 앱 A→B로 전환한 뒤 붙여넣으면 B가 선택되고 A로 복귀하지 않음 (P1 회귀).
- 패널 포커스 상태에서 패널 열기 직전 외부 창으로 복원하여 Ctrl+V 전송.
- 빠른 메모 대상 확보 시 외부 HWND 복원 경로를 호출하지 않음.
- Escape/닫기/붙여넣기 후 닫기 설정 on/off의 동일한 대상 처리.
- WPF/OS 실창 포커스 전환은 순수 단위 테스트만으로 보장하지 않고 수동 GUI 검증에 포함.
- 한글 키 경로 수정 시 기존 KoreanInputModule/KeyButton/InputService 테스트 전체를 실행하고, 새 분기에서 Unicode 추적 길이와 태그된 SendInput 재진입 방지를 검증.

### 수동 검증 체크리스트 (사용자 확인 필요)
1. 일반 사용자 권한 + OS IME 한국어 상태에서 빠른 메모 입력칸에 `ㅎㅏㄴㄱㅡㄹ`을 입력해 `한글`로 조합되는지 확인.
2. 동일 상황에서 메모와 외부 입력창을 오가며 포커스/IME 조합이 깨지지 않는지 확인.
3. 관리자 권한/VirtualKey 모드가 필요한 별도 배포 구성에서 같은 시나리오 확인 — 현재 보안 정책을 우회하지 않음.
4. 파일 탐색기 검색 필드에 검색어를 입력한 상태에서 클립보드 항목을 선택: 검색 필드에 정확히 붙고 다른 입력창은 변하지 않음.
5. 빠른 메모에 커서를 둔 상태에서 클립보드 항목을 선택: 메모에 정확히 붙고 외부 앱은 변하지 않음.
6. 패널 닫기 설정 OFF: 앱 A에서 패널을 연 뒤 붙여넣고, 앱 B로 이동해 같은 패널에서 다시 붙여넣기 → B에 들어가고 A는 바뀌지 않음.
7. 앱 A에서 연 패널을 다른 앱으로 전환한 뒤 패널이 비활성 상태에서 항목 선택하는 실제 조작 경로가 있는 경우, 최신 사용자 선택 앱이 우선되는지 확인.
8. 붙여넣기 후 닫기 설정 ON/OFF, 클릭/Enter, Esc/✕ 모두 검증.
9. 유효하지 않은 대상 창(앱 종료)에서 항목 선택 시 다른 AltKey 창이나 무관한 앱에 텍스트가 들어가지 않음.

## 7. 완료 기준

- 세 증상이 각각 재현 기준선과 수정 후 결과로 기록됨.
- 탐색기 검색 필드·빠른 메모·일반 외부 필드에서 대상 혼선 없이 붙여넣기.
- P1 시나리오에서 stale foreground 재사용이 재현되지 않음.
- 자동화 테스트와 전체 `dotnet test AltKey.Tests/AltKey.Tests.csproj` 통과.
- 수동 GUI 검증이 필요한 코드 변경은 사용자가 확인하기 전 커밋하지 않으며, 완료 시 AGENTS.md의 샌드박스 번들까지 제공.

## 8. 가정·질문

- 가정: 세 증상을 하나의 입력 대상/포커스 문제로 뭉뚱그리지 않고, 한글 IME 경로와 클립보드 대상 복원 경로를 별도 조사한 뒤 관련 부분만 수정한다.
- 가정: 현재 증상 재현 환경은 이 Windows 11 AltKey 실행 환경이며, 관리자 권한 여부·OS IME 상태·대상 앱 버전은 조사 로그로 확인한다.
- 빠른 메모에서 원하는 동작은 OS IME(VirtualKey) 기반 자모 조합이며, Unicode 입력을 최종 해결책으로 고정하지 않는다.
