# Skill: 지능형 릴리즈

스크립트에만 의존하지 않고, 변경 사항을 읽어 버전 업데이트와 릴리즈 준비를 직접 판단하기 위한 작업 지침입니다.

## 목표
- 최근 변경을 분석해 적절한 버전 타입을 결정합니다.
- `.csproj` 버전을 일관되게 올립니다.
- 릴리즈 커밋, 태그, 푸시까지 한 흐름으로 마무리합니다.

## 실행 순서

### 1. 변경 사항 분석 및 버전 타입 결정
1. `git describe --tags --abbrev=0`으로 마지막 릴리즈 태그를 확인합니다.
2. `git log $latestTag..HEAD --oneline`으로 이전 태그 이후 변경을 확인합니다.
3. `git status --short`로 아직 커밋되지 않은 변경도 확인합니다.
4. 아래 기준으로 버전 타입을 결정합니다.
   - **Major**: 하위 호환이 깨지는 큰 변경
   - **Minor**: 새로운 기능 추가
   - **Patch**: 버그 수정, 문서 수정, 리팩터링 등 기타 변경
5. 닫기/트레이/복귀 UX처럼 사용자가 바로 체감하는 동작 변경은 기능 추가가 아니어도 릴리즈 노트 요약에 반드시 포함합니다.

### 2. 현재 버전 확인
1. `AltKey/AltKey.csproj`에서 아래 값을 확인합니다.
   - `<Version>`
   - `<AssemblyVersion>`
   - `<FileVersion>`

### 3. 버전 계산 및 파일 업데이트
1. 결정한 타입에 따라 새 버전을 계산합니다.
2. `.csproj`의 버전 관련 태그를 모두 같은 버전으로 올립니다.

### 4. 릴리즈 직전 문서 점검
1. `README.md`가 실제 동작을 설명하는지 확인합니다.
2. `docs/index.html`의 FAQ나 소개 문구가 최신 동작과 맞는지 확인합니다.
3. 위키 반영이 필요한 변경이면 `skills/wiki-update.md` 흐름까지 끝났는지 확인합니다.

### 5. 릴리즈 커밋 생성
1. 커밋 메시지는 한국어로 작성합니다.
   - 제목: `release: vX.X.X`
   - 본문: 핵심 변경 요약
2. `git add .`를 실행합니다.
3. `git commit -m "[제목]" -m "[본문]"`으로 커밋합니다.

### 6. 태그 및 푸시
1. `git tag vX.X.X`로 태그를 만듭니다.
2. `git push origin main`
3. `git push origin --tags`

## 주의 사항
- 버전만 올리고 사용자 안내 문구가 실제 동작과 어긋난 상태로 배포하지 않습니다.
- 릴리즈 노트에는 사용자가 체감하는 변화, 특히 설정 위치/기본값/복귀 방법 변화를 빠뜨리지 않습니다.
- 이 지침은 `scripts/release.ps1`를 보완하거나 대체하는 기준으로 사용합니다.
