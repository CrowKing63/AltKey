# Skill: 위키 문서 업데이트 및 게시

코드 변경 뒤 `Wiki/AltKey.wiki` 문서를 실제 동작과 맞게 고치고, 필요하면 위키 저장소에 바로 반영하기 위한 작업 지침입니다.

## 목표
- 최근 변경이 사용자 매뉴얼에 영향을 주는지 빠르게 판단합니다.
- 관련 위키 페이지를 정확히 찾아 수정합니다.
- 변경이 있으면 위키 저장소에 커밋하고 `origin/master`로 게시합니다.

## 실행 순서

### 1. 최근 변경 분석
1. `git log -n 5 --oneline`으로 최근 작업 이력을 확인합니다.
2. 필요하면 `git show [COMMIT_ID]` 또는 `git diff HEAD~1`로 실제 변경 내용을 확인합니다.
3. 아래 질문으로 위키 업데이트 필요 여부를 판단합니다.
   - 새로운 기능이 추가되었는가?
   - 기존 기능의 조작 방식이나 옵션이 바뀌었는가?
   - 닫기, 트레이 숨김, 복귀 경로처럼 사용자가 바로 체감하는 창 동작 UX가 바뀌었는가?
   - 설정 화면의 문구, 옵션 위치, 기본값이 바뀌었는가?
   - 접근성 관련 흐름(L1/L2/L3, TTS, 스캔, 포커스 이동 등)이 바뀌었는가?

### 2. 대상 위키 페이지 찾기
1. `docs/wiki-meta-manual.md`의 문서 매핑을 참고해 관련 위키 페이지를 찾습니다.
2. 닫기/트레이/복귀 UX가 바뀐 경우에는 최소한 아래 페이지를 함께 검토합니다.
   - `시스템-트레이`
   - `설정`
   - `자주-묻는-질문`
3. 필요하면 Home, 개요, 시작하기 같은 진입 페이지도 함께 확인합니다.

### 3. 문서 수정
1. `Wiki/AltKey.wiki/{페이지명}.md`를 열어 실제 동작에 맞게 수정합니다.
2. `docs/wiki-meta-manual.md`의 문체, 제목, 링크 규칙을 따릅니다.
3. 사용자 입장에서 바로 이해되도록 다음 내용을 분명히 씁니다.
   - 어디서 켜고 끄는지
   - 기본 동작이 무엇인지
   - 실수했을 때 어떻게 되돌리는지
   - 관련 설정이나 트레이 메뉴가 서로 연동되는지
4. `README.md`, `docs/index.html`, 위키 문구가 같은 의미 축을 쓰는지도 확인합니다.

### 4. 위키 변경 확인
1. `git -C "C:\Users\UITAEK\AltKey\Wiki\AltKey.wiki" status --short`로 변경 파일을 확인합니다.
2. 변경이 없다면 작업을 종료합니다.

### 5. 커밋 및 게시
1. 커밋 메시지는 한국어로 작성합니다.
   - 제목: `docs: [변경 요약]`
   - 본문: 수정한 페이지와 핵심 변경 내용
2. 아래 순서로 실행합니다.
   - `git -C "C:\Users\UITAEK\AltKey\Wiki\AltKey.wiki" add .`
   - `git -C "C:\Users\UITAEK\AltKey\Wiki\AltKey.wiki" commit -m "[제목]" -m "[본문]"`
   - `git -C "C:\Users\UITAEK\AltKey\Wiki\AltKey.wiki" push origin master`

## 주의 사항
- 기능을 추가, 변경, 삭제한 경우 같은 작업 안에서 위키 반영까지 끝내는 것을 기본으로 합니다.
- 위키 저장소는 메인 프로젝트와 별도의 Git 저장소이므로 모든 git 명령에 `-C` 경로를 명시합니다.
- PowerShell 환경이므로 `&&` 대신 `;` 또는 순차 실행을 사용합니다.
